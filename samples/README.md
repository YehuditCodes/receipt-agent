# מסמכים לדוגמה

16 מסמכים אמיתיים (שמות, טלפונים ומספרי לקוח הושחרו). אלה שמראים החלטה של האג'נט:

| קובץ | מה קורה |
|---|---|
| `01.jpg` | עסק חדש: הקטגוריה (מזון) נבחרת לפי הפריטים, והשם המלא מגיע מרשם החברות |
| `02.jpg` | צולם לרוחב: פייתון מסובב אותו. הקטגוריה (תחבורה) נבחרת לפי הפריט "שטיפת רכב" |
| `03.jpeg` | מותג מוכר ושם חוקי: H&M (מאצ' ריטייל בע"מ) |
| `04.jpeg` | כתב יד: האג'נט מבקש לאשר את הסכום. הקטגוריה (לימודים) נבחרת לפי בית הספר לנהיגה, ולא לפי השם "שרותי מזון" |
| `06.pdf` | קבלה דיגיטלית כקובץ PDF |
| `07.jpeg` | תשלום בשני כרטיסים, וחריגה מתקציב הביגוד |
| `08.jpg` | אותו עסק כמו `01`: הקבלה שעולה שנייה מזוהה מהזיכרון ונרשמת בלי שאלה |
| `09.png` | הזמנה ולא קבלה: האג'נט מציע לא לרשום אותה, כדי שההוצאה לא תיספר פעמיים |
| `10.png` | חשבון: נרשם לפי תאריך ההפקה, ולא לפי תקופת החיוב |
| `11.png` | קבלה בדולרים: הסכום מומר לשקלים לפי השער היציג של בנק ישראל\* |
| `13.png` | שולם בתו קנייה ובאשראי: שני התשלומים נבדקים מול הסה"כ |
| `15.jpeg` | קבלה מקומטת: אם השנה נקראת לא נכון, האג'נט שואל על התאריך |

`05.jpg`, `12.jpg`, `14.png` ו-`16.jpg` הן קבלות רגילות (שלוש מהן צולמו לרוחב), כדי לראות שהאג'נט מסתדר גם עם מסמכים פשוטים.

\* בקבלה הזו הסכום שונה ידנית ל-$250 לצורך ההדגמה.

**כפילות:** מעלים שוב את אחד הקבצים, גם בשם אחר – הוא מזוהה ומדולג.

**תלוש משכורת** לא נכלל כאן מטעמי פרטיות. הכנסות מתלוש נבדקו על תלוש אמיתי בסט הבדיקה.

**שמות ניטרליים בכוונה:** האג'נט רואה את שם הקובץ, ושם כמו "order-not-a-receipt" היה רומז לו על התשובה.

**אם משהו נראה קצת שונה מצילומי המסך:** האג'נט בנוי לעבוד עם קריאה לא מושלמת. מודל ראייה לא תמיד קורא פרט קשה באותה צורה – למשל לוגו בצילום לרוחב או ספרה בכתב יד. לכן כשמשהו לא ודאי האג'נט שואל, ופייתון לא מאפשר לרשום ערך שלא נבדק. בריצה חדשה שם של עסק או שאלה אחת עשויים להיות שונים, אבל שום דבר לא נרשם בטעות בלי ידיעת המשתמש.

**איך מריצים:** בדפדפן (`python web_app.py`) מעלים את הקבצים אחד אחד; בטרמינל מעתיקים אותם ל-`inbox/` ומריצים `python main.py`.
