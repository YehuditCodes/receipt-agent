## הרעיון

אג'נט שמקבל תמונות של קבלות ותלושי משכורת, מבין אם זו הוצאה או הכנסה, משייך לקטגוריה,
ומציג סיכום חודשי (הכנסות, הוצאות לפי קטגוריה, יתרה) כולל התראה על חריגה מתקציב.

## החלטות שהתקבלו

| נושא | החלטה | למה |
|---|---|---|
| שפה | Python | הספרייה הרשמית של OpenAI, קוד קצר, הדוגמה במטלה בפייתון |
| מודל | OpenAI `gpt-4o-mini` | מומלץ במטלה, זול, קורא תמונות. ניתן להחלפה ב-config |
| API Key | משתנה סביבה `OPENAI_API_KEY` | לא בקוד, לא ב-GitHub |
| אחסון | קבצי JSON (`data/`) | אין צורך בדאטאבייס; בעתיד – SQLite |
| ממשק | טרמינל (עם `rich`) | המטלה לא דורשת ממשק; React רק כבונוס אם יישאר זמן |
| ארכיטקטורה | האג'נט מופרד מהממשק | האג'נט שולח "אירועים" ושואל דרך `AgentUI`; אפשר להוסיף ממשק ווב בלי לגעת בלוגיקה |
| קבלת החלטות | ה-LLM בוחר כלים בעצמו (function calling) | לא רצף קבוע – זה מה שהופך את זה לאג'נט |
| חישובים | בפייתון, לא ב-LLM | מספרים מדויקים |
| חנות לא מוכרת | מסווג לפי הפריטים; אם לא בטוח – שואל וזוכר (`memory.json`) | לא מנחש, ולומד |
| תנאי עצירה | סיום המטרה, או מגבלת צעדים (~25) | אג'נט לא רץ לנצח |

## הכלים של האג'נט

| כלי | מה עושה |
|---|---|
| `list_documents` | אילו קבצים מחכים לעיבוד ב-`inbox/` |
| `read_document(path, detail)` | קורא תמונה ומחזיר נתונים מובנים (סוג, חנות, תאריך, פריטים, סכום) |
| `add_transaction(...)` | שומר הוצאה/הכנסה |
| `find_duplicate(...)` | בודק אם המסמך כבר נרשם |
| `get_monthly_summary(month)` | הכנסות, הוצאות לפי קטגוריה, יתרה, חריגות תקציב |
| `ask_user(question)` | שואל את המשתמשת כשמשהו לא ברור |

### החלטות שהאג'נט מקבל
- קבלה (הוצאה) או תלוש (הכנסה)?
- סכום הפריטים לא תואם לסה"כ → לקרוא שוב ברזולוציה גבוהה
- כבר נרשם → לדלג
- קטגוריה לא ברורה → לשאול ולזכור
- חריגה מתקציב → להתריע
- תמונה לא קריאה → לדלג ולדווח

## קטגוריות (הוחלט)

**הוצאות:**
| קטגוריה | דוגמאות |
|---|---|
| מזון וקניות | סופר, מכולת, שוק |
| מסעדות ובתי קפה | מסעדה, משלוח אוכל, קפה |
| חשבונות בית | חשמל, מים (גיחון), גז, ארנונה, אינטרנט, טלפון |
| דיור | שכירות, ועד בית |
| תחבורה | דלק, רב-קו, מונית, חניה |
| בריאות ופארם | סופר-פארם, תרופות, רופא |
| ביגוד והנעלה | חנויות בגדים ונעליים |
| לימודים | שכר לימוד, ספרים, קורסים |
| פנאי ובילויים | קולנוע, מנויים, טיולים |
| אחר | כל מה שלא מתאים |

**הכנסות:** משכורת, אחר

- **קטגוריה ≠ גוף:** "חברת החשמל" / "הגיחון" הם הגוף (שדה `business`), "חשבונות בית" היא הקטגוריה. הסיכום נעשה לפי קטגוריות.
- **זיכוי** (החזרת מוצר) אינו הכנסה – נרשם כהוצאה **שלילית** באותה קטגוריה.
- **תלוש משכורת** – נרשם סכום הנטו.

## פורמט הנתונים (נסגר במשימה 1)

`data/transactions.json` – רשימת תנועות:
```json
{
  "id": "t001",
  "type": "expense",
  "date": "2026-10-12",
  "amount": 250.40,
  "category": "מזון וקניות",
  "business": "שופרסל דיל",
  "source_file": "receipt_shufersal.jpg",
  "items": ["חלב", "לחם", "עגבניות"],
  "added_at": "2026-10-25T14:32:10"
}
```

`data/memory.json` – מה שהאג'נט למד:
```json
{ "business_categories": { "אצל משה": "מזון וקניות" } }
```

שני קבצים נפרדים: הנתונים (מה קנית) נפרדים מהידע של האג'נט (מה הוא למד) – אפשר לאפס חודש בלי שהאג'נט ישכח.

## אחסון – כללים (נסגר במשימה 1)
- מזהה תנועה: מספר רץ `t001`, `t002`… (אחד מעל הגבוה הקיים)
- קובץ שלא קיים = רשימה/זיכרון ריקים (ריצה ראשונה)
- קובץ פגום או במבנה לא צפוי → עוצרים עם הודעה ברורה בעברית, **לא נוגעים בקובץ** (אין אובדן נתונים)
- כתיבה בטוחה: לקובץ זמני ואז החלפה – קריסה באמצע לא משחיתה את הקובץ
- תמונה לא קריאה → הודעה "התמונה לא ברורה, העלי שוב" (ייושם במשימה 3)
- גיבוי: בכל שמירה הגרסה הקודמת נשמרת כ-`<name>.bak`; בקובץ פגום ההודעה מפנה לגיבוי (שחזור ידני – בלי לשאול)
- קבצים שנערכו ב-Notepad (תו BOM נסתר) נקראים כרגיל
- `config.check_config()` תופס טעויות בהגדרות (תקציב לקטגוריה לא קיימת, מספר לא חיובי) – **לקרוא לה בתחילת `main.py` (משימה 5)**
- אי אפשר למנוע ממי שיושב מול המחשב לפתוח את הקובץ (כמו בכל תוכנה); ההגנה היא שאין אובדן נתונים. הצפנה – הוחלט שלא (מסבך בלי צורך)
- `data/` כולו לא עולה ל-GitHub (כולל `.bak` ו-`.tmp` – גם בהם נתונים אישיים)

## מקרי קצה – תזכורות למשימות הבאות
| משימה | לטפל ב |
|---|---|
| 2 – כלים | בדיקת תנועה לפני רישום: סכום מספרי, תאריך תקין, סוג expense/income, קטגוריה מהרשימה; זיכוי = סכום שלילי; אותה קבלה בשני שמות קבצים (כפילות לפי עסק+תאריך+סכום); חודש בלי תנועות בסיכום; `inbox/` ריק |
| 3 – קריאת תמונה | תמונה מטושטשת/חתוכה → "התמונה לא ברורה, העלי שוב"; קובץ שאינו תמונה או סיומת לא נתמכת; תמונה שאינה קבלה/תלוש; קובץ גדול מדי; מטבע זר; קבלה בלי תאריך או תאריך עתידי; סכום פריטים ≠ סה"כ; תשובה לא תקינה מהמודל |
| 5 – לולאת האג'נט | `check_config()` בהתחלה; מפתח API חסר; המודל קורא לכלי שלא קיים או עם פרמטרים שגויים; הגעה ל-`MAX_STEPS` → עצירה ודיווח מה הושלם ומה לא |
| 6 – שגיאות | אין אינטרנט / timeout; מגבלת קצב (rate limit) / אין קרדיט; המשתמשת לוחצת Ctrl+C באמצע; תשובה ריקה ל-`ask_user` |
