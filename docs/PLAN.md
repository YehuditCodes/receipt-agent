> המסמך הזה הוא נקודת הפתיחה של כל צ'אט חדש: מה נדרש, מה הוחלט, ואיפה אנחנו עומדים.

## הרעיון

אג'נט שמקבל תמונות של קבלות ותלושי משכורת, מבין אם זו הוצאה או הכנסה, משייך לקטגוריה,
ומציג סיכום חודשי (הכנסות, הוצאות לפי קטגוריה, יתרה) כולל התראה על חריגה מתקציב.

## החלטות שהתקבלו

| נושא | החלטה | למה |
|---|---|---|
| שפה | Python | הספרייה הרשמית של OpenAI, קוד קצר, הדוגמה במטלה בפייתון |
| מודל | OpenAI `gpt-4o-mini` | מומלץ במטלה, זול, קורא תמונות. ניתן להחלפה ב-config |
| API Key | משתנה סביבה `OPENAI_API_KEY` | לא בקוד, לא ב-GitHub |
| אחסון | קבצי JSON (`data/`) | אין צורך בדאטאבייס; בעתיד – SQLite |
| ממשק | טרמינל (עם `rich`) | המטלה לא דורשת ממשק; React רק כבונוס אם יישאר זמן |
| ארכיטקטורה | האג'נט מופרד מהממשק | האג'נט שולח "אירועים" ושואל דרך `AgentUI`; אפשר להוסיף ממשק ווב בלי לגעת בלוגיקה |
| קבלת החלטות | ה-LLM בוחר כלים בעצמו (function calling) | לא רצף קבוע – זה מה שהופך את זה לאג'נט |
| חישובים | בפייתון, לא ב-LLM | מספרים מדויקים |
| חנות לא מוכרת | מסווג לפי הפריטים; אם לא בטוח – שואל וזוכר (`memory.json`) | לא מנחש, ולומד |
| תנאי עצירה | סיום המטרה, או מגבלת צעדים (~25) | אג'נט לא רץ לנצח |

## הכלים של האג'נט

| כלי | מה עושה |
|---|---|
| `list_documents` | התמונות ב-`inbox/`, ולכל אחת האם כבר נרשמה |
| `read_document(path, detail)` | קורא תמונה ומחזיר נתונים מובנים (סוג, חנות, תאריך, פריטים, סכום) |
| `add_transaction(...)` | שומר הוצאה/הכנסה |
| `find_duplicate(date, amount, source_file)` | מחזיר תנועות שאולי הן אותו מסמך – האג'נט מחליט |
| `remember_business(business, category)` | זוכר קטגוריה של עסק (רק אחרי אישור המשתמשת) |
| `get_monthly_summary(month)` | הכנסות, הוצאות לפי קטגוריה, יתרה, חריגות תקציב |
| `ask_user(question)` | שואל את המשתמשת כשמשהו לא ברור |

### החלטות שהאג'נט מקבל
- קבלה (הוצאה) או תלוש (הכנסה)?
- סכום הפריטים לא תואם לסה"כ → לקרוא שוב ברזולוציה גבוהה
- כבר נרשם → לדלג
- קטגוריה לא ברורה → לשאול ולזכור
- חריגה מתקציב → להתריע
- תמונה לא קריאה → לדלג ולדווח

## קטגוריות (הוחלט)

**הוצאות:**
| קטגוריה | דוגמאות |
|---|---|
| מזון וקניות | סופר, מכולת, שוק |
| מסעדות ובתי קפה | מסעדה, משלוח אוכל, קפה |
| חשבונות בית | חשמל, מים (גיחון), גז, ארנונה, אינטרנט, טלפון |
| דיור | שכירות, ועד בית |
| תחבורה | דלק, רב-קו, מונית, חניה |
| בריאות ופארם | סופר-פארם, תרופות, רופא |
| ביגוד והנעלה | חנויות בגדים ונעליים |
| לימודים | שכר לימוד, ספרים, קורסים |
| פנאי ובילויים | קולנוע, מנויים, טיולים |
| אחר | כל מה שלא מתאים |

**הכנסות:** משכורת, אחר

- **קטגוריה ≠ גוף:** "חברת החשמל" / "הגיחון" הם הגוף (שדה `business`), "חשבונות בית" היא הקטגוריה. הסיכום נעשה לפי קטגוריות.
- **זיכוי** (החזרת מוצר) אינו הכנסה – נרשם כהוצאה **שלילית** באותה קטגוריה.
- **תלוש משכורת** – נרשם סכום הנטו.

## פורמט הנתונים (נסגר במשימה 1)

`data/transactions.json` – רשימת תנועות:
```json
{
  "id": "t001",
  "type": "expense",
  "date": "2026-10-12",
  "amount": 250.40,
  "category": "מזון וקניות",
  "business": "שופרסל דיל",
  "source_file": "receipt_shufersal.jpg",
  "items": ["חלב", "לחם", "עגבניות"],
  "added_at": "2026-10-25T14:32:10"
}
```

`data/memory.json` – מה שהאג'נט למד:
```json
{ "business_categories": { "אצל משה": "מזון וקניות" } }
```

שני קבצים נפרדים: הנתונים (מה קנית) נפרדים מהידע של האג'נט (מה הוא למד) – אפשר לאפס חודש בלי שהאג'נט ישכח.

## אחסון – כללים (נסגר במשימה 1)
- מזהה תנועה: מספר רץ `t001`, `t002`… (אחד מעל הגבוה הקיים)
- קובץ שלא קיים = רשימה/זיכרון ריקים (ריצה ראשונה)
- קובץ פגום או במבנה לא צפוי → עוצרים עם הודעה ברורה בעברית, **לא נוגעים בקובץ** (אין אובדן נתונים)
- כתיבה בטוחה: לקובץ זמני ואז החלפה – קריסה באמצע לא משחיתה את הקובץ
- תמונה לא קריאה → הודעה "התמונה לא ברורה, העלי שוב" (ייושם במשימה 3)
- גיבוי: בכל שמירה הגרסה הקודמת נשמרת כ-`<name>.bak`; בקובץ פגום ההודעה מפנה לגיבוי (שחזור ידני – בלי לשאול)
- קבצים שנערכו ב-Notepad (תו BOM נסתר) נקראים כרגיל
- `config.check_config()` תופס טעויות בהגדרות (תקציב לקטגוריה לא קיימת, מספר לא חיובי) – **לקרוא לה בתחילת `main.py` (משימה 5)**
- אי אפשר למנוע ממי שיושב מול המחשב לפתוח את הקובץ (כמו בכל תוכנה); ההגנה היא שאין אובדן נתונים. הצפנה – הוחלט שלא (מסבך בלי צורך)
- `data/` כולו לא עולה ל-GitHub (כולל `.bak` ו-`.tmp` – גם בהם נתונים אישיים)

## כלים – כללים (נסגר במשימה 2)
- כל כלי מחזיר `{"ok": true, ...}` או `{"ok": false, "error": "..."}` ולא זורק שגיאה – המודל קורא את השגיאה ומחליט (לתקן, לקרוא שוב, לשאול). רק `StorageError` (קובץ פגום) עוצר הכול
- **תמונות נשארות ב-`inbox/`**; `list_documents` מסמן `already_recorded` לפי `source_file`. לא מזיזים קבצים – פחות דברים שיכולים להישבר. העברה ל-`done/` אפשרית בעתיד
- **כפילויות:** `find_duplicate` מחזיר מועמדים לפי תאריך+סכום (או אותו שם קובץ), כולל שם העסק; המודל משווה ("שופרסל" / "שופרסל דיל") ומחליט – החלטה אמיתית של האג'נט
- **זיכרון עסקים:** כלי נפרד `remember_business`, נקרא רק אחרי שהמשתמשת אישרה. **משימה 5:** להכניס את `business_categories` מ-`memory.json` להנחיות המודל, כדי שידע עסקים מוכרים
- **תקציב:** סטטוס `ok` / `near` (מ-80%, `BUDGET_WARNING_RATIO` ב-config) / `over` (מעל 100%)
- בדיקות ב-`add_transaction`: סוג, תאריך YYYY-MM-DD תקין ולא עתידי, סכום מספרי ≠ 0, הכנסה חיובית בלבד, קטגוריה מהרשימה לפי הסוג, עסק ושם קובץ לא ריקים
- נבדק ידנית בסקריפט על תיקייה זמנית (לא נוגע ב-`data/`): רישום, זיכוי, 10 קלטים שגויים, כפילות בשם קובץ אחר, זיכרון, סיכום עם `near`/`over`, חודש ריק

## איך מדברים עם המודל – ארבע השכבות

האג'נט הוא לולאה: המודל מחליט על צעד, פייתון מבצע, התוצאה חוזרת למודל, והוא מחליט על הצעד הבא.
ארבע שכבות של טקסט מכוונות את המודל:

| # | שכבה | מה זה | איפה בקוד | משימה | מי כותב → מי קורא | רכיב אג'נט שזה ממלא (מהמטלה) | דוגמה |
|---|---|---|---|---|---|---|---|
| 1 | **פרומפט מערכת** (system prompt) | המטרה והכללים. נשלח פעם אחת, בתחילת השיחה | `agent.py` | 5 | אנחנו → המודל | **קבלת מטרה** + **תנאי סיום** | "המטרה: לעבד את כל המסמכים החדשים ולהציג סיכום. לפני רישום – בדוק כפילות. כשהכול טופל – הצג סיכום וסיים" |
| 1א | זיכרון בתוך הפרומפט | העסקים שהאג'נט כבר למד, נטען מ-`memory.json` לתוך שכבה 1 | `agent.py` (קורא `storage.load_memory()`) | 5 | הקוד → המודל | **קבלת החלטות** (מסווג בלי לשאול שוב) | "עסקים מוכרים: אצל משה = מזון וקניות" |
| 2 | **תיאורי הכלים** (tool definitions) | "תפריט" לכל כלי: שם, מה הוא עושה ומתי להשתמש בו, פרמטרים וסוגיהם | `agent.py` (רשימת JSON לכל כלי ב-`tools.py`) | 5 | אנחנו → המודל | **שימוש בכלי** – המודל בוחר כלי לפי התיאור | `find_duplicate`: "מחזיר תנועות שאולי הן אותו מסמך. השווה את שמות העסקים והחלט" |
| 3 | **פרומפט קריאת תמונה** | קריאה נפרדת למודל עם התמונה בלבד, שמחזירה JSON מובנה | `tools.py` → `read_document` | 3 | אנחנו → המודל (vision) | איסוף מידע (הכלי היחיד שמשתמש ב-AI) | "החזר JSON: סוג, עסק, תאריך, פריטים, סה\"כ. לא קריא → readable: false" |
| 4 | **תוצאות הכלים** | מה שכל כלי מחזיר, כולל שגיאות. נכנס לשיחה כהודעה | `tools.py` (כל הכלים) | 2 ✅ | הקוד → המודל | **בחינת התוצאה** – המודל מחליט לפי התוצאה | `{"ok": false, "error": "הסכום חייב להיות מספר"}` → המודל מתקן ושולח שוב |

**עקרונות:**
- **בפרומפט כותבים כללים ולא סדר פעולות.** לא כותבים "שלב 1: list, שלב 2: read". המודל מחליט על הסדר בעצמו – זה ההבדל בין אג'נט לתוכנה רגילה (10% מהציון).
- **שמות הפרמטרים בשכבה 2 = השמות בפונקציות של `tools.py`** (`date`, `amount`...). המודל שולח אותם, והקוד מעביר אותם ישר לפונקציה.
- **הודעות השגיאה בשכבה 4 נכתבות בשביל המודל:** הן אומרות מה לא תקין ואיך לתקן, כדי שיוכל להמשיך לבד.
- **חישובים לא נמצאים באף פרומפט.** את הסכומים והתקציבים מחשב פייתון (`get_monthly_summary`), והמודל רק מציג אותם.

**סבב אחד בלולאה – דוגמה:**
```
[שכבה 1+2 נשלחות]  המודל: "אקרא ל-list_documents"
[שכבה 4]           פייתון: {"documents": [{"file": "r1.jpg", "already_recorded": false}]}
                   המודל: "אקרא ל-read_document('r1.jpg')"
[שכבה 3]           פייתון שולח את התמונה למודל → {"business": "אצל משה", "total": 87, ...}
                   המודל: "העסק מופיע בזיכרון (שכבה 1א) → מזון וקניות. אבדוק כפילות"
[שכבה 4]           פייתון: {"possible_duplicate": false}
                   המודל: "אקרא ל-add_transaction(...)"  ... וכך הלאה עד הסיכום
```
